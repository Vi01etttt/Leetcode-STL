# Leetcode-STL

这个仓库用来长期保存 LeetCode 刷题记录、题解、复盘笔记和面试准备材料。

目标不是只把题做完，而是沉淀出可以反复复习的解法库：

- 每道题保留题目理解、思路、复杂度、易错点和代码。
- 按专题整理常见套路，比如数组、双指针、滑动窗口、二分、动态规划、图、树、栈队列等。
- 对面试高频题做二刷、三刷记录。
- 记录自己卡住的原因，避免同类问题反复踩坑。

## 推荐目录结构

```text
.
├── problems/          # 每道题一个目录
├── topics/            # 按算法专题整理总结
├── cpp-stl/           # C++ 算法题常用容器与函数速查
├── plans/             # 阶段性刷题计划
├── templates/         # 题解模板和代码模板
└── tools/             # 辅助脚本
```

## C++ 容器速查

常用数据结构的创建方式、函数用法和易错点见 [C++ 算法题常用容器速查](./cpp-stl/README.md)。

## 单题目录规范

建议每道题使用这种格式：

```text
problems/
└── 0001-two-sum/
    ├── README.md
    ├── solution.py
    └── solution_notes.md
```

其中：

- `README.md`：题目、思路、复杂度、易错点。
- `solution.py`：最终代码。
- `solution_notes.md`：二刷/三刷、不同解法、复盘记录。

## 新增一道题

可以用脚本快速生成目录：

```powershell
python tools/new_problem.py 1 "Two Sum"
```

会生成：

```text
problems/0001-two-sum/
```

## 刷题建议

第一阶段建议优先覆盖面试高频基础：

1. 数组与哈希表
2. 双指针与滑动窗口
3. 栈与队列
4. 二分查找
5. 链表
6. 树与 DFS/BFS
7. 回溯
8. 动态规划
9. 图
10. 堆与贪心

每道题至少记录三件事：

- 我为什么想到这个解法？
- 这个解法的关键不变量是什么？
- 下次遇到类似题，我应该识别出什么信号？
